# v7.4.0 Migration Guide

This guide outlines the breaking changes in v7.4.0 of the Cloudflare TypeScript
SDK and the steps needed to update your code. The `cloudflare migrate` tool has
not been updated for these changes; update affected call sites by hand.

Each section below describes what changed, who is affected, and provides
before/after code using real imports and signatures from the SDK.

---

### `magicCloudNetworking`

#### 1. The entire `magicCloudNetworking` resource was removed

**What changed:**
The top-level `magicCloudNetworking` resource and all of its sub-resources
(`catalogSyncs`, `catalogSyncs.prebuiltPolicies`, `onRamps`,
`onRamps.addressSpaces`, `cloudIntegrations`, `resources`) have been removed.

**Impact:**
Any access to `client.magicCloudNetworking.*` will no longer compile, and imports
of the associated types (`CatalogSync`, `OnRamp`, `AddressSpace`,
`CloudIntegration`, etc.) will fail.

**Before (v7.3.0):**

```ts
const syncs = await client.magicCloudNetworking.catalogSyncs.list({ account_id });
```

**After (v7.4.0):**

```ts
// No replacement in the SDK. Remove calls to client.magicCloudNetworking.*
```

**Actions Needed:**

1. Remove all `client.magicCloudNetworking.*` call sites.
2. Remove imports of `magicCloudNetworking` types.

---

### `registrar`

#### 2. `registrar.domains` was removed

**What changed:**
The `registrar.domains` sub-resource has been removed.

**Impact:**
`client.registrar.domains.*` no longer compiles.

**Actions Needed:**

1. Remove all `client.registrar.domains.*` call sites.

---

### `tenants`, `accounts`, `tenantCustomNameservers`, `browserRendering`

#### 3. Removed methods

**What changed:**
The following methods and their response types were removed:

- `accounts.payBadDebt.create()` (`PayBadDebtCreateResponse`)
- `tenants.get()` (`Tenant`)
- `tenants.accountTypes.list()` (`AccountTypeListResponse`)
- `tenants.entitlements.get()` (`TenantEntitlements`)
- `tenants.memberships.list()` (`TenantMembership`)
- `tenantCustomNameservers.create()`, `.delete()`, `.get()`
  (`TenantCustomNameserverCreateResponse`, `TenantCustomNameserverDeleteResponse`,
  `TenantCustomNameserverGetResponse`)
- `browserRendering.devtools.browser.connect()`, `.launch()`
- `browserRendering.devtools.browser.page.get()`

**Impact:**
Calls to these methods no longer compile, and imports of their response types fail.

**Actions Needed:**

1. Remove the affected call sites and type imports.

---

### `magicTransit`, `organizations`, `precursor`, `brandProtection`, `intel`, `Shared`

#### 4. Removed types

**What changed:**
The following exported types were removed:

**Removed Types:**

- `Shared.LoadBalancerPreview`
- `brandProtection.Info`, `brandProtection.Submit`
- `intel.whois.Whois`
- `precursor.EnforcementRule`, `precursor.EnforcementRuleParam`
- `magicTransit.sites.wans.WANStaticAddressingParam`
- `organizations.organizationProfile.OrganizationProfileParam`

**Impact:**
Imports of these types will fail to compile. For `WANStaticAddressingParam` and
`OrganizationProfileParam`, the request-param type was merged into the base model
type.

**Before (v7.3.0):**

```ts
import type { WANStaticAddressingParam } from 'cloudflare/resources/magic-transit/sites/wans';
import type { OrganizationProfileParam } from 'cloudflare/resources/organizations/organization-profile';

const addressing: WANStaticAddressingParam = {
  /* ... */
};
```

**After (v7.4.0):**

```ts
import type { WANStaticAddressing } from 'cloudflare/resources/magic-transit/sites/wans';
import type { OrganizationProfile } from 'cloudflare/resources/organizations/organization-profile';

const addressing: WANStaticAddressing = {
  /* ... */
};
```

**Actions Needed:**

1. Replace `WANStaticAddressingParam` with `WANStaticAddressing`.
2. Replace `OrganizationProfileParam` with `OrganizationProfile`.
3. Remove imports of the other removed types.

---

### `rulesets`, `tenants.accounts`, `user.tenants`, `diagnostics`, `zeroTrust.resourceLibrary`

#### 5. Pagination and return type changes

**What changed:**
Several `list()` methods changed their return/pagination type:

**Affected Types:**

- `rulesets.list()`: `RulesetListResponsesCursorPagination` -> `RulesetListResponse` (no longer paginated)
- `rulesets.phases.versions.list()`: `VersionListResponsesSinglePage` -> `VersionListResponse` (no longer paginated)
- `rulesets.versions.list()`: `VersionListResponsesSinglePage` -> `VersionListResponse` (no longer paginated)
- `tenants.accounts.list()`: `TenantAccountsSinglePage` -> `AccountListResponsesV4PagePaginationArray`
- `user.tenants.list()`: `OrganizationsSinglePage` -> `TenantListResponsesSinglePage`
- `diagnostics.endpointHealthchecks.list()`: `EndpointHealthcheckListResponse` -> `EndpointHealthcheckListResponsesSinglePage` (now paginated)
- `zeroTrust.resourceLibrary.applications.list()`: `ApplicationListResponsesSinglePage` -> `ApplicationListResponsesCursorPaginationAfter`
- `zeroTrust.resourceLibrary.categories.list()`: `CategoryListResponsesSinglePage` -> `CategoryListResponsesCursorPaginationAfter`

**Impact:**
Auto-pagination (`for await (const item of ...)`) still works. Code that assigns
the page object to a typed variable, reads page-level fields, or relies on a
specific cursor type must be updated. For `rulesets.*`, the result is no longer a
paginated page object at all.

**Before (v7.3.0):**

```ts
// rulesets.list previously returned a cursor-paginated page
const page = await client.rulesets.list({ account_id });
for await (const ruleset of page) {
  console.log(ruleset.id);
}
```

**After (v7.4.0):**

```ts
// rulesets.list now returns a plain response object (not paginated)
const response = await client.rulesets.list({ account_id });
for (const ruleset of response.result ?? []) {
  console.log(ruleset.id);
}
```

**Actions Needed:**

1. For `rulesets.*` list methods, stop using auto-pagination and read the result
   directly from the response object.
2. For the `SinglePage` -> `V4PagePaginationArray` / `CursorPaginationAfter`
   changes, update any page-level field access to match the new page type.
3. Update typed variable annotations to the new return types.

### `tenants.accounts`, `zeroTrust.access.users.lastSeenIdentity`, `accounts.subscriptions.bulk`, `workersForPlatforms`, `vectorize`

#### 6. Changed method return types and signatures

**What changed:**

- `tenants.accounts.list()` now accepts a params object and returns
  `AccountListResponse` elements (the `TenantAccounts` element type was removed).
- `zeroTrust.access.users.lastSeenIdentity.get()` returns
  `LastSeenIdentityGetResponse` instead of `Identity`.
- `accounts.subscriptions.bulk.create()` returns `BulkCreateResponse`
  (previously `BulkCreateResponse | null`).
- `workersForPlatforms.dispatch.namespaces.scripts.tags.delete()` returns
  `TagDeleteResponse` (previously `TagDeleteResponse | null`).
- `vectorize.indexes.getByIDs()` returns `IndexGetByIDsResponsesSinglePage`
  (previously `IndexGetByIDsResponse | null`).

**Impact:**
Type assertions and null checks on these return values may no longer type-check.

**Before (v7.3.0):**

```ts
const identity: Identity = await client.zeroTrust.access.users.lastSeenIdentity.get(userID, {
  account_id,
});
```

**After (v7.4.0):**

```ts
const identity: ZeroTrust.Access.Users.LastSeenIdentityGetResponse =
  await client.zeroTrust.access.users.lastSeenIdentity.get(userID, { account_id });
```

**Actions Needed:**

1. Update variable type annotations to the new return types.
2. Remove now-unnecessary `null` checks where `| null` was dropped.

---

### `aiSearch.namespaces.instances`

#### 7. `name` path parameter renamed to `namespace`

**What changed:**
The `name` path parameter on all `aiSearch.namespaces.instances` methods (and the
nested `instances.jobs` and `instances.items` resources) was renamed to
`namespace`. Endpoints changed from
`/accounts/{account_id}/ai-search/namespaces/{name}/...` to
`/accounts/{account_id}/ai-search/namespaces/{namespace}/...`.

**Impact:**
The positional argument stays in the same position, so most call sites continue
to compile. Code that referenced the parameter by name (for example in generated
request types) must use `namespace`.

**Before (v7.3.0):**

```ts
await client.aiSearch.namespaces.instances.list(name, { account_id });
```

**After (v7.4.0):**

```ts
await client.aiSearch.namespaces.instances.list(namespace, { account_id });
```

**Actions Needed:**

1. Rename local variables/arguments from `name` to `namespace` where it improves
   clarity; no positional reordering is required.

---

## Summary

Breaking changes in v7.4.0:

1. `magicCloudNetworking` resource and all sub-resources removed.
2. `registrar.domains` removed.
3. Removed methods on `accounts.payBadDebt`, `tenants`, `tenants.accountTypes`,
   `tenants.entitlements`, `tenants.memberships`, `tenantCustomNameservers`, and
   `browserRendering.devtools.browser` (+ `.page`).
4. Removed types: `Shared.LoadBalancerPreview`, `brandProtection.Info`/`Submit`,
   `intel.whois.Whois`, `precursor.EnforcementRule`/`EnforcementRuleParam`,
   `WANStaticAddressingParam` (use `WANStaticAddressing`), and
   `OrganizationProfileParam` (use `OrganizationProfile`).
5. Pagination/return type changes on `rulesets.*`, `tenants.accounts`,
   `user.tenants`, `diagnostics.endpointHealthchecks`, and
   `zeroTrust.resourceLibrary` list methods.
6. Changed return types/signatures on `tenants.accounts.list()`,
   `zeroTrust.access.users.lastSeenIdentity.get()`,
   `accounts.subscriptions.bulk.create()`,
   `workersForPlatforms.dispatch.namespaces.scripts.tags.delete()`, and
   `vectorize.indexes.getByIDs()`.
7. `aiSearch.namespaces.instances` `name` path parameter renamed to `namespace`.
